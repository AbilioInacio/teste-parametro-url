Ambiente e banco de aula

Objetivo: Prepare um banco isolado e confira a versão do servidor.

TXT · linhas 13–24Slide 11 · Preparação do laboratório

SQL, verificação e significado

Execute cada unidade e observe sua consulta de conferência antes de seguir. Copie o bloco completo.
01Configuração da sessão
SQL · pronto para copiar
SET @OLD_SQL_SAFE_UPDATES := @@SESSION.sql_safe_updates;
SET SESSION SQL_SAFE_UPDATES = 0;
O que este bloco ensina

Guarde a proteção atual e desative Safe Updates apenas para este laboratório.

Confira no Workbench: A opção ficará em 0 até ser restaurada na última etapa.
02Criar a base isolada
SQL · pronto para copiar
DROP DATABASE IF EXISTS aula_bd;
CREATE DATABASE aula_bd
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
USE aula_bd;
O que este bloco ensina

A base aula_bd é recriada e selecionada. A exclusão anterior é proposital e restrita ao laboratório.

Confira no Workbench: Confirme que você está em uma conexão de treinamento.
03Conferir ambiente
SQL · pronto para copiar
SELECT
  VERSION() AS versao_mysql,
  @@SESSION.sql_safe_updates AS safe_updates;
O que este bloco ensina

VERSION() mostra a versão do servidor; a segunda coluna exibe a configuração da sessão.

Confira no Workbench: safe_updates = 0
DICA da aula: DROP DATABASE apaga toda a base aula_bd. Utilize apenas o ambiente de laboratório. Atenção: esta preparação apaga e recria somente a base aula_bd. Não execute em produção.

Resultado esperado

A consulta final mostra a versão e safe_updates = 0.
Para interpretar: O Workbench e o servidor MySQL são a mesma coisa?

Se precisar conferir

Execute os blocos na ordem. Use a mesma conexão no MySQL Workbench. O HTML orienta a atividade, mas não executa comandos SQL.

Por que pode surgir um erro?
Verifique se as etapas anteriores foram executadas, se a tabela/coluna existe e se o usuário possui as permissões necessárias. Falhas intencionais aparecem comentadas no TXT; não as descomente ao executar tudo.
